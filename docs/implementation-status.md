## Current demonstrated checks

GitHub Actions now runs ten jobs including Python coverage and correctness lint, adversarial and dependency security checks, CodeQL Python/TypeScript, native Temporal and PostgreSQL integration/migration checks, and a gated attested **simulator-only** release bundle. The build is Docker-free. See [CI/CD controls](ci-cd.md). A green pipeline does **not** prove external deployment safety or eliminate unreachable code.

What CI **does not** prove: no full production incident recovery, no real external adapter, no load/HA numbers, no trusted production user authentication, no empirical risk calibration and no promoted AI policy. Never report a smoke PASS as deployment approval.

## Conditions to revisit before production

Implement real tenant identity, independently scoped operator/reviewer/release roles, complete audit/secret controls, adapter conformance for each external target, full B1 failure/replay testing, realistic workload budgets, independent held-out E5 measurements, and a signed human-controlled E6 rollout. Live infrastructure effects and learned-policy activation must remain disabled until those safeguards are validated.

## Explicit release blockers

- **Identity and governance:** Production token verification and tenant/role checks have code and mock-key tests, but need real IdP configuration and independent penetration review. Server-side security-admin revocation fences pending grants, but does not substitute for IdP role-change ingestion; least-privilege service identities and independent signing/release roles remain missing.
- **Real-world capability:** No real target adapter is enabled. The simulator is the only effect destination; third-party idempotency/fencing, oracle isolation, audit retention and recovery under crashes are unproven.
- **Measured intelligence:** The optional AI advisory is a constrained, off-by-default read-only prototype. E5 uses public deterministic fixtures, not blinded independent recovery trials; confidence calibration and regression evidence are missing.
- **Operations:** Native Linux systemd templates and a static fail-closed unit audit are now present for all core service roles. These are not deployed to multiple hosts. Native PostgreSQL/Temporal CI passes migrations and simulator end-to-end flows; a native, isolated PostgreSQL dump/restore rehearsal checks synthetic consent and identity revocations, IdP replay fencing, unresolved effect receipts, pending Temporal start replay state and stable workflow IDs, capsule state and RLS settings. A new bounded, read-only cross-system recovery audit compares attempted and acknowledged starts against verified Temporal workflow identity and classifies unresolved or inconsistent simulator receipts, without dispatching or changing state. It now supports cursor pagination, a fixed timezone-aware observation cutoff, and a pinned outbox-ID high-water bound across pages, with cross-page duplicate START intent checks. Receipt scan truncation now identifies which selected incidents have missing receipt evidence instead of marking all selected incidents as truncated; a truncated global scan still exits nonzero. Recovery-audit continuation now rejects a cursor above its pinned high-water ID, rather than returning an empty clean-looking page for an inconsistent audit range. Duplicate START-intent counts now also honor the pinned high-water ID, so a backdated duplicate inserted after page one cannot retroactively change a later page's findings; a fresh audit can detect it. The read-only G3 audit also includes aged dead-lettered workflow starts even when their attempt counter is zero, and flags any dead-lettered but unacknowledged start for operator review; this detects contradictory durable state without dispatching a workflow. The fixed observation timestamp is validated fail-closed even at datetime range boundaries, so an underflow cannot crash an unattended audit with an unclassified exception. The receipt audit also rejects malformed or negative observed target versions on FAILED simulator receipts instead of silently treating the record as consistent; this is local data-integrity checking, not an independent effect outcome. The read-only receipt audit additionally checks persisted plan digests for canonical lowercase SHA-256 hex and positive fencing tokens; invalid simulator receipts are flagged for inspection without changing their state. This validates local receipt shape only, not permit authenticity or external fencing. This is still not a consistent database snapshot or an independent multi-host recovery drill. It does not prove high availability, Temporal backup restore, restore under corruption, multi-host load, penetration resistance, accessibility or disaster recovery.
- **Policy promotion:** E6 active exposure remains deliberately disabled. No smoke PASS, reviewer credential, or successful unit test is a sufficient production release authorization.

The completion definition is **measured acceptance of every relevant test in the PDF**, not the presence of a similarly named file or endpoint.
