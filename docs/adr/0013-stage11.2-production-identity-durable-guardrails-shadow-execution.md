## 1. Context and Problem Statement

Following Stage 11.1's critical security remediation, an architectural and adversarial review (including EGM Goldfish red-team stress testing) identified three foundational architectural gaps that prevented enterprise production deployment:

1. **Development-Only Password Directory:** Identity was anchored to hardcoded development credentials (`PRECONFIGURED_USERS`). In enterprise environments, OpsBlaze must delegate authentication to an authoritative OpenID Connect / OAuth 2.0 Identity Provider (IdP) via RFC 7662 token introspection, bind identities to server-managed tenant memberships, enforce a 0-second revocation guarantee, and permanently reject client-asserted roles.
2. **Synchronous Guardrail Coupling & Outbox Contamination:** Automated safety guardrails in Stage 11.1 ran synchronously inside incident state transitions or unreliably via in-memory hooks. Furthermore, the `outbox` table lacked kind partitioning, meaning any secondary task (guardrails or shadow evaluations) placed into the outbox could be inadvertently claimed by the B1 incident dispatcher, triggering catastrophic dispatch failures or silent data loss.
3. **Passive Shadow Mode & Mid-Flight Safety Races:** Stage 11 designated a `SHADOW` release state, but candidate models were never actually executed against live evidence snapshots, or risked exercising consequential authority (minting B2 fences, B3 receipts, or dispatching P2 approval cards). Moreover, if an operator activated an emergency kill switch while a candidate shadow evaluation was in-flight, stale candidate recommendations could be persisted into audit logs and misattributed.

Stage 11.2 resolves every vulnerability across Gates A through I.

## 2. Architectural Decisions & Technical Specification

### Decision 1: Enterprise Identity Exchange & RFC 7662 Introspection (Gate A)
- **RFC 7662 Token Introspection:** Introduced `POST /v1/auth/exchange`. Clients present an opaque or JWT bearer token issued by the enterprise IdP. OpsBlaze validates the token against the IdP's introspection endpoint via `TokenIntrospectionClient`.
- **SSRF Defense-in-Depth:** Introspection URLs are validated against cloud metadata IPs (`169.254.169.254`, `metadata.google.internal`), loopback addresses (`127.0.0.1`), link-local addresses, and non-HTTPS schemes in production. DNS resolution checks prevent DNS rebinding attacks.
- **Server-Managed `IdentityMembership`:** Roles and tenant memberships are strictly server-managed in PostgreSQL table `identity_membership`. The upstream token's immutable subject (`sub`) and issuer (`iss`) are mapped to a tenant-specific `actor_id` and verified `roles`. Client-supplied roles or actor IDs in request bodies are forbidden (`extra='forbid'`, HTTP 422).
- **0-Second Revocation Guarantee:** The authenticated request dependency `get_authenticated_tenant_id` executes a synchronous lookup of `IdentityMembership.is_active` in PostgreSQL for every authenticated request. When an administrator deactivates a membership, access terminates immediately on the very next HTTP request without waiting for JWT TTL expiration.
- **Production Password Deprecation:** `auth_allow_password_login` defaults to `False` in production. Any attempt to use `/v1/auth/login` when disabled returns HTTP 403 Forbidden.

### Decision 2: Durable Kind-Partitioned Guardrail Execution & Reconciled Alembic Linear DAG (Gate B)
- **Database Schema Extensions & Reconciled Alembic Linear DAG:**
  - `0009_stage11_1_revoked_tokens.py` (`stage11_1_001_revoked_tokens`): Created PostgreSQL `revoked_token` table for persistent JWT JTI revocation.
  - `0010_stage11_2_guardrail_outbox.py` (`stage11_2_001_guardrail_outbox`): Extended `outbox` with `kind`, `dedupe_key`, `payload`, `lease_owner`, `last_error`, `incident_id`, and partial unique index `uq_outbox_dedupe_in_flight`.
  - `0011_stage11_2_identity_membership.py` (`stage11_2_002_identity`): Created `identity_membership` table with `uq_identity_membership_lookup` on `(idp_issuer, idp_subject, tenant_id)`.
  - `0012_stage11_2_outbox_identity.py` (`stage11_2_001_outbox_identity`): Staged outbox extensions with safe idempotency checks.
  - `0013_stage11_2_reconcile_outbox_identity.py` (`stage11_2_003_reconcile` - head): Forward-reconciled migration harmonizing outbox indices (`uq_outbox_dedupe_in_flight`, `ix_outbox_kind_pending`), dropping redundant unique constraints (`uq_outbox_dedupe_key`), and ensuring symmetric clean downgrades without `UndefinedObjectError`. Both `opsblaze` and `opsblaze_test` databases are at `stage11_2_003_reconcile (head)`.
- **Complete Decoupling of B1 Dispatcher:**
  - `OutboxRepository.claim_batch` explicitly filters `Outbox.kind.in_(('INCIDENT_START', 'incident_start'))`, ensuring B1 incident workflows never claim guardrail or shadow items.
  - Bulk recovery and cancellation operations (`transition_status`, `reconcile_status_projection_forward`, and `recovery.py`) are strictly scoped to `kind == 'INCIDENT_START'`, preventing cancellation of guardrail or shadow tasks.
- **Atomic Incident Enqueue:** When an incident transitions to terminal state (`VERIFIED`, `FAILED`, `NEEDS_REVIEW`, `CANCELLED`) and carries a `policy_release_id`, `IncidentRepository.transition_status` atomically enqueues `Outbox(kind="RELEASE_GUARDRAIL", dedupe_key=f"guardrail:{release.id}")` in the SAME database transaction.
- **Durable `GuardrailOutboxDispatcher`:**
  - Claims pending guardrail rows using `FOR UPDATE SKIP LOCKED` with a 15-second worker lease (`available_at = now + 15s`).
  - Calls `ReleaseGuardrailService.evaluate_and_enforce_guardrails`.
  - Idempotently acknowledges terminal release states (`ROLLED_BACK`, `REVOKED`, deleted test releases).
  - Handles retries with exponential backoff (`min(60s, base * 2^(attempt-1))`) and dead-letters after 5 attempts.

### Decision 3: Isolated Shadow Execution & Consequential Authority Fence (Gate C)
- **Deterministic Shadow Routing:** In `PolicyRouterService.route_incident`, when the active release is in state `SHADOW`, the live incident is routed 100% to the INCUMBENT policy bundle. Simultaneously, an outbox task `Outbox(kind="RELEASE_SHADOW_EVALUATION", dedupe_key=f"shadow:{release.id}:{incident.id}")` is atomically enqueued.
- **Dual Bundle Integrity Verification:** Before executing candidate or incumbent bundles, `ShadowExecutor` verifies RFC 8785 canonical JSON serialization, SHA-256 payload digest, and HMAC-SHA256 signature for both bundles. Any tampering trips a Class 1 invariant breach (`INVARIANT_BREACH`) on the release.
- **Identical Evidence Snapshot Replay:** Both candidate and incumbent evaluate the exact same immutable evidence context.
- **Zero Consequential Authority Guarantee:** Candidate shadow executions are physically prohibited from interacting with B2 resource reservations, B3 effect receipts, P2 approval cockpit cards, or A2 mutation grants.
- **Mid-Flight Kill-Switch CAS Invalidation:** Before recording observations, `ShadowExecutor` executes a row-locked reload of `PolicyRelease` (`with_for_update()`). If the kill switch was activated or the release was rolled back/revoked while evaluation was in-flight:
  - Candidate findings are discarded immediately.
  - An audit event `SHADOW_RESULT_DISCARDED_KILL_SWITCH` is recorded.
  - No `SHADOW_OBSERVATION` is persisted and candidate metrics are untouched.

### Decision 4: Multi-Worker Lifespan Management (Gate D)
- `backend/api/main.py` lifespan coordinates background dispatchers when `enable_in_process_dispatchers = True`.
- Graceful shutdown handles `asyncio.CancelledError`, signals `stop_event`, drains tasks with a 5.0-second timeout, and safely disposes the SQLAlchemy engine.

## 3. Threat Model & Security Invariants (STRIDE)

| Threat Category | Mitigated Vulnerability | Enforcement Mechanism |
|---|---|---|
| **Spoofing** | Untrusted caller asserting arbitrary `actor_id` or `roles` | RFC 7662 token exchange maps upstream subject to server-managed `IdentityMembership`. Client cannot provide roles. |
| **Tampering** | Shadow candidate bundle altered in database post-creation | Dual cryptographic signature and digest verification (RFC 8785 + HMAC-SHA256) before every shadow evaluation. |
| **Repudiation** | Actions taken during shadow evaluation without audit lineage | All shadow outcomes recorded in `ReleaseEventAudit` with `consequential_authority=False` and hash lineage. |
| **Information Disclosure** | SSRF to internal metadata endpoints via IdP introspection | IP and hostname blocking (`169.254.169.254`, `metadata.google.internal`, loopback), HTTPS enforcement, redirects disabled. |
| **Denial of Service** | Unbounded outbox retries or stuck worker leases | Explicit lease timeout (15s/30s), exponential backoff, dead-letter cap (5 attempts), and `SKIP LOCKED`. |
| **Elevation of Privilege** | Candidate policy in shadow executing production mutations | Zero access to B2 fence, B3 receipt, P2 approval, or A2 mutation grants. Mid-flight CAS invalidation on kill switch. |

---

## 4. Operational Invariants

1. **Fail-Closed Gate:** If upstream IdP is unreachable, token introspection fails, or membership is deactivated, OpsBlaze rejects requests with HTTP 401/403.
2. **Zero Consequential Leakage:** A candidate in `SHADOW` state shall never cause external effect receipts or mutate infrastructure under any circumstances.
3. **At-Least-Once Guardrails:** Every terminal incident progression guarantees a durable outbox entry that will be evaluated even in the event of immediate process crashes.
4. **Idempotency:** Re-executing guardrail checks or shadow evaluations on already rolled-back releases succeeds idempotently without duplicate side effects.
