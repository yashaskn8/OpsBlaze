# OpsBlaze security policy

## Supported versions

Security triage covers the current `main` branch and the most recent Community
candidate identified in the [release verification record](docs/engineering/RELEASE_VERIFICATION.md).
Community support covers the single-host simulator. Include the tested commit
and archive SHA-256 when reporting an issue in a candidate.

## Private reporting

Use [GitHub's private vulnerability form](https://github.com/yashaskn8/OpsBlaze/security/advisories/new).
Keep security details out of public issues, pull requests and Discussions
while triage is in progress.

Describe the affected behavior, impact, verified source commit, and relevant
platform and dependency versions. Use disposable simulator data and redact
credentials, personal data, raw logs and incident evidence.

## Response and disclosure

The maintainer aims to acknowledge a report within seven calendar days.
Triage confirms the affected scope, assigns a severity, and establishes a
private update and remediation schedule with the reporter. The maintainer
coordinates disclosure through a GitHub security advisory where appropriate.
Please coordinate publication timing in the private report.
